# 4️⃣ 低级设计文档（LLD）

版本：1.5  
作者：Tei  
日期：2026-07-16

## 1. 目的

本文档在现有实现基础上，补齐 Rebalance、Asset Type Region、Asset Name UI 移除和 Settings 保存反馈的低级设计，并继续统一术语：

- `settings`
- `exchange_rates`
- `asset_types.region`
- `asset.name deprecated`
- `rebalance snapshot`
- `i18n fallback`
- `fx 状态`

## 2. 模块划分（vNext）

### 2.1 Renderer（React）

职责：

- 渲染多语言文案。
- 提供语言切换入口。
- 提供显示币种切换入口。
- 展示汇率状态（正常/过期/缺失）。
- 提供数据导出/导入入口与结果提示。
- 从资产 UI 中移除 Name 字段。
- 在 Asset Types UI 中显示和编辑 Region。
- 提供 Add New Rebalance 按钮与 Rebalance 草稿编辑界面。
- 在 Settings 保存 Preferences / FX Rates 后显示结果反馈。

### 2.2 i18n 模块

职责：

- 加载语言资源。
- 根据 `settings.app.language` 选择当前语言。
- 执行缺失翻译回退。
- 覆盖新增文案：Region、Add New Rebalance、Rebalance 草稿、Settings 保存反馈。

回退规则（固定）：

1. 当前语言
2. `en-US`
3. `zh-CN`
4. 文案 key

### 2.3 fx/exchange-rate 模块

职责：

- 读取 `settings.app.display_currency`。
- 查询 `exchange_rates`。
- 提供资产金额换算。
- 输出 `fx 状态`。

`fx 状态` 枚举：

- `ok`：汇率存在且未过期
- `stale`：汇率存在但已过期
- `missing`：目标汇率缺失

### 2.4 Service 层

职责：

- 聚合资产。
- 调用 fx 模块进行换算。
- 汇总 fx 状态信息。
- 将结果返回给 UI。
- 提供数据库导入/导出能力（调用数据库模块）。
- 提供 Asset Type Region 读写。
- 提供 Rebalance 草稿创建与保存。

## 3. 配置键设计（settings）

- `app.language`: `zh-CN` / `en-US` / `ja-JP`
- `app.display_currency`: `JPY` / `CNY` / `USD`
- `fx.cache_ttl_days`: 正整数

## 4. IPC 合约（新增/扩展）

### 4.1 settings / i18n 相关

- `getSettings` -> 入参 `无` -> 返回 `{ [key]: value }`
- `setSetting` -> 入参 `{ key, value }` -> 返回 `{ success, changes } | { error }`

### 4.2 fx 相关

- `getExchangeRates` -> 入参 `无` -> 返回 `[{ base_currency, quote_currency, rate, source, updated_at }]`
- UI 显示 `updated_at` 时统一调用日期格式化，只展示 `YYYY-MM-DD`，不展示具体时分秒。
- `upsertExchangeRate` -> 入参 `{ baseCurrency, quoteCurrency, rate }` -> 返回 `{ success, changes } | { error }`
- 设置页直接调用 `upsertExchangeRate` 写入数据库（手工维护汇率）

### 4.3 asset / asset type 相关

- `getAssets` -> 返回资产列表；普通 UI 不返回或不渲染 `name`。
- `addAsset` -> 入参 `{ date, typeId, amount, currency }`，不要求 `name`。
- `modifyAsset` -> 入参 `{ id, date, typeId, amount, currency }`，不要求 `name`。
- `getAssetTypes` -> 返回 `[{ id, name, region }]`。
- `addAssetType` -> 入参 `{ name, region? } | name`，兼容旧调用。
- `modifyAssetType` -> 入参 `{ id, name, region? } | (id, name)`，兼容旧调用。
- `deleteAssetType` -> 入参 `{ id }`。

### 4.4 rebalance 相关（规划）

- `getRebalanceTemplate` -> 入参 `无` -> 返回：

```json
{
  "sourceDate": "2026-07-12",
  "rebalanceDate": "2026-07-16",
  "items": [
    {
      "sourceAssetId": 1,
      "typeId": 10,
      "typeName": "US Stocks",
      "region": "US",
      "amount": 1000,
      "currency": "USD"
    }
  ]
}
```

- `saveRebalance` -> 入参：

```json
{
  "date": "2026-07-16",
  "items": [
    { "typeId": 10, "amount": 1200, "currency": "USD" }
  ]
}
```

- `saveRebalance` -> 返回：

```json
{ "success": true, "insertedCount": 3, "date": "2026-07-16" }
```

失败时返回：

```json
{ "success": false, "error": { "code": "VALIDATION_ERROR", "message": "..." } }
```

### 4.5 导入/导出相关

- `exportDatabase` -> 入参 `无` -> 行为：打开保存对话框导出 `.db` -> 返回 `{ success, path } | { canceled } | { error }`
- `importDatabase` -> 入参 `无` -> 行为：打开文件对话框导入 `.db` -> 返回 `{ success, willRestart, backupPath } | { canceled } | { error }`

### 4.6 汇总接口（规划）

- `assets:getSummary`（规划）-> 入参 `{ displayCurrency? }` -> 返回

```json
{
  "displayCurrency": "JPY",
  "total": 123456.78,
  "fx": {
    "status": "ok|stale|missing",
    "updatedAt": "2026-02-15",
    "missingPairs": ["USD->JPY"],
    "excludedCount": 2
  }
}
```

## 5. UI 渲染约定

### 5.1 多语言渲染

- 所有固定文案从 i18n 字典读取。
- 缺失翻译必须按 fallback 规则显示，不允许空白。

### 5.2 多币种渲染

- Dashboard/Chart 使用同一 `displayCurrency`。
- 当 `fx.status = missing`：
  - 页面显示“缺少汇率”提示；
  - 显示未计入汇总数量。
- 当 `fx.status = stale`：
  - 页面显示“汇率已过期”提示；
  - 允许继续显示换算结果。

### 5.3 Asset Name 移除

- Dashboard 表格不渲染 Name 列。
- Assets 表格不渲染 Name 列。
- Add/Edit Asset 表单不渲染 Name 输入。
- Duplicate / Rebalance 复制资产时不依赖 Name。
- 旧数据中的 `name` 只作为兼容字段存在。

### 5.4 Asset Type Region

- Asset Types 列表显示列：ID、Name、Region、Actions。
- Add Asset Type 表单包含 Name 与 Region。
- Edit Asset Type 表单包含 Name 与 Region。
- Region 可以为空。

### 5.5 Settings 保存反馈

- `Save Preferences` 成功后显示成功消息。
- `Save Preferences` 失败后显示错误消息。
- `Save FX Rates` 成功后显示成功消息。
- `Save FX Rates` 失败后显示错误消息。
- 反馈应位于 Settings 页面可见区域，例如按钮附近或页面顶部状态区。

## 6. 换算规则

### 6.1 单资产换算

- 若资产币种 == 显示币种，直接使用原值。
- 否则查找对应汇率并换算。
- 缺失汇率时，该资产标记为 excluded，不计入 total。

### 6.2 汇总换算

- 仅累计可换算或同币种资产。
- 返回 `excludedCount` 和 `missingPairs` 供 UI 提示。
- Dashboard 使用最新日期的资产集合。
- Chart 按日期分别汇总资产集合。

## 7. Rebalance 设计细节

### 7.1 创建草稿

1. 查询 `MAX(assets.date)` 得到 `sourceDate`。  
2. 读取 `sourceDate` 下全部资产。  
3. 关联 `asset_types` 获取 type name 和 region。  
4. 创建草稿：`rebalanceDate = today`，items 保留 typeId、typeName、region、currency、amount。  
5. UI 展示草稿列表，用户只修改日期和金额。

### 7.2 保存草稿

1. 校验日期非空。  
2. 校验每行 `amount` 为有效数字，建议整数输入。  
3. 校验每行 `typeId` 和 `currency` 有效。  
4. 禁用保存按钮，防止重复提交。  
5. 事务内批量插入新 `assets` 记录。  
6. `name` 写入 `NULL` 或空字符串。  
7. 保存成功后返回插入数量与日期。  
8. UI 显示成功反馈并刷新 Dashboard / Chart。

### 7.3 无历史数据

- 若不存在任何资产，`getRebalanceTemplate` 返回空状态。
- UI 显示“请先新增资产”并提供 Add Asset 入口。

## 8. 离线与缓存策略（LLD 细化）

- 汇率仅从本地 `exchange_rates` 读取。
- 用户手工更新汇率后，立即覆盖同币种对记录（`UNIQUE(base_currency, quote_currency)`）。
- 过期判定：按 `updated_at + fx.cache_ttl_days` 计算有效期。

## 9. 错误与状态返回约定

统一错误结构：

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR|NOT_FOUND|DB_ERROR|FX_RATE_MISSING|REBALANCE_EMPTY_TEMPLATE",
    "message": "..."
  }
}
```

fx 缺失为业务状态优先，不默认抛异常；仅在调用方明确要求 strict mode 时返回 `FX_RATE_MISSING`。

Rebalance 错误示例：

- `REBALANCE_EMPTY_TEMPLATE`: 没有可复制的上一期资产快照
- `REBALANCE_INVALID_DATE`: 日期为空或格式无效
- `REBALANCE_INVALID_AMOUNT`: 某行金额无效
- `REBALANCE_SAVE_FAILED`: 批量保存失败

导入/导出相关错误示例：

- `IMPORT_INVALID_FILE`: 导入文件不存在或不可读
- `IMPORT_INVALID_SCHEMA`: 缺少核心表
- `IMPORT_INTEGRITY_FAILED`: 数据库完整性校验失败
- `EXPORT_IO_ERROR`: 导出写文件失败

## 10. 数据库迁移执行器（已落地）

### 10.1 文件布局

- 迁移脚本目录：`main/migrations/`
- 当前基线脚本：`main/migrations/001_initial_schema.sql`
- 数据库模块：`main/database.js`
- 启动入口：`main.js`（`await assetService.init()` 后再 `createWindow()`）

### 10.2 执行流程

1. 解析并排序 `main/migrations/NNN_*.sql`。  
2. 读取 `PRAGMA user_version` 作为当前版本。  
3. 若存在待执行脚本：
   - 先备份数据库文件到 `userData/backups/`；
   - 对每个脚本执行 `BEGIN -> SQL -> PRAGMA user_version=NNN -> COMMIT`。  
4. 任一脚本失败时 `ROLLBACK`，抛错并终止应用启动。

### 10.3 路径策略

- 开发环境数据库：`data/assets.db`
- 打包环境数据库：`app.getPath('userData')/assets.db`
- 备份文件命名：
  - `assets.v<from>-to-v<to>.<timestamp>.db`

### 10.4 首启基线数据

由 `001_initial_schema.sql` 一次性建立与注入：

- 表结构：`asset_types`、`assets`、`settings`、`exchange_rates`
- 默认设置：`app.language=en-US`、`app.display_currency=USD`、`fx.cache_ttl_days=90`
- 初始资产类型：`美股`、`中国股票`、`现金人民币`
- 初始资产（仅空库）：`现金人民币`，`10000 CNY`

## 11. 导入/导出执行细节（已落地）

### 11.1 导出流程

1. 设置页触发 `exportDatabase`。  
2. 主进程打开保存对话框并获得目标路径。  
3. 数据库模块先持久化当前内存库，再复制 `assets.db` 到目标路径。  
4. UI 显示导出结果路径。

### 11.2 导入流程

1. 设置页触发 `importDatabase`，先进行覆盖确认。  
2. 主进程打开文件对话框选择 `.db`。  
3. 数据库模块校验导入文件：
   - `PRAGMA integrity_check = ok`
   - 存在核心表：`asset_types`、`assets`、`settings`、`exchange_rates`  
4. 校验通过后先备份当前数据库到 `userData/backups/`。  
5. 复制导入文件覆盖当前库，随后执行 migration 到最新版本。  
6. 返回成功并触发应用重启。
