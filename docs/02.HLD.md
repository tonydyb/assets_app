# 2️⃣ 系统架构设计书（High-Level Design, HLD）

版本：1.3  
作者：Tei  
日期：2026-07-16

## 1. 系统概述

### 1.1 系统目标

构建一个：

- 完全本地运行
- 不依赖互联网
- 可长期使用（20年以上）
- 数据可控、可迁移
- 支持资产管理、资产类型 Region、Rebalance、图表、导入/导出与备份
- 支持多语言与多币种显示

### 1.2 技术选型（摘要）

| 组件 | 技术 |
| --- | --- |
| 桌面容器 | Electron |
| UI层 | React |
| 数据库 | SQLite（`sql.js`） |
| 图表 | Canvas API |
| 样式 | MVP.css + 自定义样式 |


### 2.1 架构说明

- Renderer 负责界面渲染与用户交互。
- Main 负责 IPC、业务编排、配置读取、汇率查询、数据访问。
- Asset Service 负责资产、资产类型、汇总、图表数据。
- Rebalance Service 负责创建 Rebalance 草稿与保存新快照。
- `i18n` 模块负责语言选择、文案加载与回退规则。
- `fx/exchange-rate` 模块负责汇率读取、币种换算与状态判定。

## 3. 模块划分

### 3.1 UI 模块（Renderer）

职责：

- 页面渲染（Dashboard / Assets / Add Asset / Rebalance / Types / Chart / Settings）
- 语言切换入口
- 显示币种切换入口
- 展示汇率更新时间与缺失汇率提示
- 提供数据库导入/导出入口（设备迁移）
- 提供 `Add New Rebalance` 入口与批量金额录入 UI
- 提供 Settings 保存成功/失败反馈

### 3.2 i18n 模块

职责：

- 管理可用语言列表（`zh-CN`、`en-US`、`ja-JP`）
- 提供默认语言（`en-US`）
- 持久化用户语言选择
- 执行缺失文案回退（`en-US` -> `zh-CN` -> key）
- 覆盖 Rebalance、Region、Settings feedback 新文案

### 3.3 fx/exchange-rate 模块

职责：

- 维护支持币种列表（`JPY`、`CNY`、`USD`）
- 提供“记账币种 -> 显示币种”换算能力
- 输出汇率更新时间
- 判定“缺失汇率”并返回可展示状态

### 3.4 业务模块（Main / Service）

职责：

- 聚合资产数据
- 管理资产类型及其 Region
- 调用 fx 模块进行换算
- 汇总 fx 状态信息
- 将结果返回给 UI
- 提供数据库导入/导出能力（调用数据库模块）
- 编排 Rebalance 草稿加载与保存

### 3.5 Rebalance 模块

职责：

- 查询最新资产日期。
- 读取最新日期下的资产列表作为模板。
- 生成默认日期为今天的 Rebalance 草稿。
- 校验每行金额。
- 批量保存为新日期资产快照。
- 防止保存中的重复提交。

### 3.6 数据模块（Data Access）

职责：

- 存取资产与资产类型。
- 存取资产类型 Region。
- 保留 `assets.name` 的兼容读取能力，但普通 UI 不依赖该字段。
- 存取设置（语言、显示币种）。
- 存取汇率表与更新时间。
- 支持数据库文件导入/导出与迁移前备份。

## 4. 关键数据流

### 4.1 多币种展示数据流

> 目标：定义 `UI -> 配置 -> 汇率服务 -> 渲染`

```mermaid
sequenceDiagram
  participant UI as Renderer UI
  participant CFG as Config/Settings
  participant FX as fx/exchange-rate
  participant SVC as Asset Service

  UI->>CFG: 读取显示币种设置
  UI->>SVC: 请求资产汇总/图表数据
  SVC->>CFG: 获取显示币种
  SVC->>FX: 按显示币种换算金额
  FX-->>SVC: 返回换算结果+缺失汇率状态+更新时间
  SVC-->>UI: 返回可渲染数据
  UI->>UI: 渲染总额/图表/提示
```

### 4.2 多语言渲染数据流

```mermaid
sequenceDiagram
  participant UI as Renderer UI
  participant CFG as Config/Settings
  participant I18N as i18n Module

  UI->>CFG: 读取当前语言
  UI->>I18N: 请求文案资源
  I18N-->>UI: 返回文案（含回退结果）
  UI->>UI: 渲染多语言界面
```

### 4.3 Rebalance 数据流

```mermaid
sequenceDiagram
  participant UI as Dashboard/Rebalance UI
  participant REB as Rebalance Service
  participant SVC as Asset Service
  participant DB as SQLite

  UI->>REB: Add New Rebalance
  REB->>SVC: 查询最新资产日期
  SVC->>DB: 读取最新日期资产列表
  DB-->>SVC: 返回资产列表
  SVC-->>REB: 返回模板资产
  REB-->>UI: 返回草稿（date=today）
  UI->>UI: 用户批量修改金额/日期
  UI->>REB: Save Rebalance
  REB->>REB: 校验金额与日期
  REB->>DB: 批量插入新日期资产快照
  DB-->>REB: 保存结果
  REB-->>UI: 成功/失败反馈
  UI->>SVC: 刷新 Dashboard/Chart
```

### 4.4 Asset Type Region 数据流

```mermaid
sequenceDiagram
  participant UI as Asset Types UI
  participant SVC as Asset Service
  participant DB as SQLite

  UI->>SVC: 新增/编辑资产类型(name, region)
  SVC->>DB: 写入 asset_types.region
  DB-->>SVC: 返回保存结果
  SVC-->>UI: 返回成功/失败
  UI->>SVC: 重新读取资产类型列表
```

### 4.5 设备迁移数据流（导入/导出）

```mermaid
sequenceDiagram
  participant UI as Renderer UI
  participant MAIN as Main Process
  participant DB as Database Module
  participant FS as Local File System

  UI->>MAIN: 触发导出/导入
  MAIN->>FS: 打开文件选择器
  MAIN->>DB: 执行导出或导入校验
  DB->>FS: 导出文件/备份当前库/替换数据库文件
  DB-->>MAIN: 返回成功或失败
  MAIN-->>UI: 返回结果提示
  MAIN->>MAIN: 导入成功后重启应用
```

## 5. 离线策略

### 5.1 本地汇率表

- 汇率数据以本地表为准，不依赖在线实时接口。
- 系统展示“汇率更新时间”，让用户判断新鲜度。

### 5.2 手工更新

- 用户可在设置页直接维护/确认汇率值。
- 更新后立即影响后续展示换算结果。
- 保存成功或失败必须显示反馈。

### 5.3 缓存过期规则

- 汇率记录定义有效期（例如 N 天，具体值由配置定义）。
- 超过有效期标记为“已过期”，UI 需提示。
- 过期不等于不可用：
  - 若仍有可用汇率，可继续换算并提示“汇率已过期”；
  - 若缺失目标汇率，显示“缺少汇率”，相关金额不计入汇总。

### 5.4 数据迁移与备份策略

- 数据库版本采用 SQLite `PRAGMA user_version` 管理。
- 启动时先执行数据库迁移，再打开主窗口（避免旧 schema 直接被业务读写）。
- 迁移脚本目录：`main/migrations/`，命名规则：`NNN_description.sql`（如 `002_add_asset_type_region.sql`）。
- 迁移执行前自动备份当前数据库文件到 `userData/backups/`。
- 每个迁移脚本在事务内执行（`BEGIN/COMMIT`），失败则 `ROLLBACK` 并终止启动。
- 数据库存储路径：
  - 开发环境：`data/assets.db`
  - 打包环境：`app.getPath('userData')/assets.db`

## 6. 非功能与约束

- 全功能可离线使用。
- 语言与显示币种设置需跨重启保持。
- 任何缺失翻译或缺失汇率必须可见提示，禁止静默失败。
- Rebalance 保存必须保留历史快照，不得覆盖上一期数据。
- Asset `Name` 字段第一阶段只从 UI 移除，不做破坏性物理删除。
- 架构优先可维护性：模块边界清晰、职责单一。
- 版本升级必须通过 migration 管理，禁止直接修改线上用户库结构。
