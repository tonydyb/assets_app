# 1️⃣ 需求规格说明书（Software Requirements Specification, SRS）

版本：1.3  
作者：Tei  
日期：2026-07-16

## 1. 项目目标

- 提供本地运行的个人资产记录系统。
- 长期可运行（目标 20 年）。
- 数据完全由用户掌控。
- 不依赖云服务。
- 支持周期性资产快照与 Rebalance 录入。
- 支持多语言、多币种、汇率换算和本地数据库迁移。

## 2. 功能需求

### 2.1 基础资产管理

- 用户可新增、查看、修改、删除资产记录。
- 用户可新增、查看、修改、删除资产类型。
- 资产记录的用户可见字段为：日期、资产类型、金额、币种。
- 资产记录不再向用户展示或要求输入 `Name` 字段。
- 为兼容历史数据库，系统可继续保留旧数据中的 `asset.name`，但普通 UI 不展示、不编辑该字段。
- 系统可展示总资产与资产趋势图。
- 系统支持数据库文件导出（`.db`）。
- 系统支持数据库文件导入（`.db`）。
- 系统支持导入前自动备份当前数据库。

### 2.2 资产类型 Region 需求

- 资产类型应支持 `Region` 字段，用于描述资产类型所属地区或市场。
- `Region` 可以为空。
- `Region` 第一阶段为自由文本，不限制固定枚举。
- 用户可在资产类型页面新增、查看、修改 `Region`。
- `Region` 应支持中文、英文、日文输入与显示。

### 2.3 Rebalance 需求

- Dashboard 应提供 `Add New Rebalance` 入口。
- 当存在历史资产快照时，用户可基于最新日期的资产列表创建新的 Rebalance。
- 系统应复制最新日期下的全部资产记录作为 Rebalance 草稿。
- Rebalance 草稿日期默认设置为当天日期，用户可修改。
- 用户只需要录入或修改各资产的最新金额。
- Rebalance 保存后，应作为新的资产快照写入数据库。
- 保存 Rebalance 不应修改上一期历史快照。
- 保存成功后，Dashboard 总资产与当前资产列表应使用最新快照。
- 保存成功后，Chart 应包含新快照日期。
- 当没有历史资产快照时，系统应提示用户先新增资产，而不是进入不可用流程。

### 2.4 多语言需求

- 系统应支持以下界面语言：
  - 简体中文（`zh-CN`）
  - English（`en-US`）
  - 日本語（`ja-JP`）
- 系统默认语言为 English（`en-US`）。
- 用户可在界面内找到语言切换入口并随时切换。
- 用户的语言选择在重启应用后仍然生效（持久化）。
- 新增的 Rebalance、Region、Settings 反馈文案也应支持多语言。
- 当某个文案在当前语言缺失时，系统应按以下顺序回退：
  1. `en-US`
  2. `zh-CN`
  3. 文案键名（用于提示缺失）

### 2.5 多币种需求

- 系统应支持以下币种：
  - `JPY`、`CNY`、`USD`
- 每条资产记录应有“记账币种”字段（资产原始币种）。
- 系统应提供“显示币种”设置，用于统一展示总额与统计结果。
- 汇率来源应为“用户可确认的本地汇率表”（由用户在设置页维护/确认）。
- 系统应显示当前汇率的更新时间，用户界面只显示日期 `YYYY-MM-DD`，不显示具体时分秒。
- 当某币种缺失到显示币种的汇率时：
  - 不进行静默换算；
  - 明确提示“缺少汇率”；
  - 对应金额在汇总中不计入，并显示受影响条目数。

### 2.6 Settings 保存反馈需求

- 用户点击 `Save Preferences` 后，系统应显示成功或失败反馈。
- 用户点击 `Save FX Rates` 后，系统应显示成功或失败反馈。
- 反馈应在用户可见位置展示，且持续足够时间让用户确认操作结果。
- 反馈文案应支持 `en-US`、`zh-CN`、`ja-JP`。
- 保存失败时不得显示会让用户误判为成功的文案。

## 3. 非功能需求

- 单机本地可运行。
- 数据格式长期可读。
- 启动简单。
- 数据可迁移。
- 关键设置在重启后保持一致。
- 数据库 schema 升级必须通过 migration 管理。
- 迁移与导入不得破坏用户既有数据。

## 4. 验收标准（用户可见行为）

### 4.1 资产 Name 移除验收

1. Dashboard 当前资产表不显示 `Name` 列。  
2. Assets 列表不显示 `Name` 列。  
3. Add Asset 表单不显示 `Name` 输入框。  
4. Edit Asset 表单不显示 `Name` 输入框。  
5. 旧数据库中存在 `asset.name` 时，应用仍可正常打开和展示资产。  
6. 新增资产不需要输入 Name 即可保存。

### 4.2 Asset Type Region 验收

1. 用户可在 Asset Types 页面新增资产类型并填写 Region。  
2. 用户可编辑已有资产类型的 Region。  
3. Region 为空时仍可保存资产类型。  
4. Region 支持中文、英文、日文文本。  
5. 应用重启后 Region 仍然显示正确。

### 4.3 Rebalance 验收

1. Dashboard 存在 `Add New Rebalance` 按钮。  
2. 点击后，系统复制最新日期的资产列表进入 Rebalance 草稿。  
3. Rebalance 草稿日期默认是当天日期。  
4. 用户可修改每个资产的金额。  
5. 保存后，数据库新增一组新日期资产记录。  
6. 上一次资产快照不被修改。  
7. Dashboard 总资产和当前资产列表更新为新日期快照。  
8. Chart 显示新日期对应的资产柱状图。  
9. 没有历史资产时，系统提示先新增资产。

### 4.4 多语言验收

1. 首次安装后，界面默认显示 English。  
2. 用户在设置中切换到 English 后，主导航、按钮、表头、提示信息全部显示英文。  
3. 用户关闭并重新打开应用后，仍保持 English。  
4. Rebalance、Region、Settings 保存反馈文案跟随语言切换。  
5. 当某一条文案在 English 缺失时，界面显示中文或英文回退文案，不出现空白。  
6. 当中英文都缺失时，界面显示该文案键名，便于定位缺失翻译。

### 4.5 多币种验收

1. 用户可在新增/编辑资产时选择币种（`JPY/CNY/USD`）。  
2. 用户可在设置中切换显示币种（例如从 `JPY` 切到 `CNY`）。  
3. 用户可在设置页直接录入并保存汇率，保存后重启应用仍生效。  
4. Dashboard 总额、图表数值会随显示币种切换而变化。  
5. 界面可看到汇率更新时间，格式为 `YYYY-MM-DD`。  
6. 当某币种缺少换算汇率时，界面明确提示“缺少汇率”，并标明有部分资产未计入汇总。  
7. 在汇率缺失场景下，系统不会把缺失汇率的资产错误计入总额。

### 4.6 Settings 保存反馈验收

1. 点击 `Save Preferences` 成功后，界面显示保存成功提示。  
2. 点击 `Save Preferences` 失败后，界面显示错误提示。  
3. 点击 `Save FX Rates` 成功后，界面显示保存成功提示。  
4. 点击 `Save FX Rates` 失败后，界面显示错误提示。  
5. 提示文案跟随当前语言显示。

### 4.7 设备迁移（导入/导出）验收

1. 用户可在设置页点击“导出数据”，将当前数据库导出为 `.db` 文件到本地指定路径。  
2. 用户可在设置页点击“导入数据”并选择 `.db` 文件，系统在导入前明确提示“将覆盖当前数据”。  
3. 导入成功后，系统自动重启，重启后展示导入后的数据。  
4. 导入非法或损坏数据库文件时，系统给出失败提示且当前数据不被破坏。  
5. 导入前系统自动备份当前数据库，可用于回滚恢复。  
6. 导入旧 schema 数据库时，系统执行必要 migration，确保 `asset_type.region` 可用。
